# 产品路线

[English](../en/roadmap.md) · [简体中文](roadmap.md)

iamllm 的目标不是托管某一个人的专属实例，而是让任何人都能在自己的服务器上，把自己发布成一个标准模型 API。每个实例服务一位“人类模型”，数据和密钥归部署者所有。

## 当前基线：可自托管的单实例产品

- Go 单二进制后端，React 管理台嵌入二进制，SQLite WAL 持久化；
- OpenAI Chat Completions / Responses、Anthropic Messages、Gemini GenerateContent；
- 文本、图片、文件、工具调用和人工流式 chunk；
- Web 与 Flutter 共用 Admin API、设备会话、草稿、已读和回答租约；
- 可撤销的 `sk-` 密钥、额度、自动回复、Webhook 通知和 Playground；
- Docker Compose 一条命令部署，不依赖外部数据库、消息队列或解释器环境。

## 下一阶段：让第一次部署更容易

1. 首次启动向导：创建管理员、生成总钥匙、设置模型名与公网地址。
2. 配置诊断：检查 HTTPS、反向代理、SSE、数据库可写性和通知 Webhook。
3. 导入/导出：实例配置 JSON、SQLite 在线备份和恢复说明。
4. 发布产物：版本化 Docker 镜像、校验和、更新日志与升级文档。
5. 契约测试：用真实 OpenAI SDK、Claude Code、OpenCode 和 Gemini SDK 跑端到端兼容矩阵。

## 移动端打磨

1. iOS 优先的系统通知、角标和深链，通知正文默认不携带完整对话。
2. 离线草稿、网络恢复后的幂等续传和跨设备冲突处理。
3. 会话搜索、快捷动作、图片与文件查看器、设备安全提醒。
4. 部署者自行配置 Bundle ID、签名、APNs/FCM 和商店资料；客户端不内置任何实例地址。

## 规模增长后再做

- PostgreSQL 仓储实现与同一套仓储契约测试；
- 多实例事件总线、跨进程回答租约和水平扩容；
- 多管理员角色与审计日志；
- 可选的对象存储和大型附件生命周期管理。

这些能力只有在真实部署规模需要时才引入。当前不增加空壳适配器、兼容层或“以后可能用到”的数据库字段。

## 明确不做

- 不在服务端伪装成真正的自动推理模型；
- 不把任何 SaaS 设为必需依赖；
- 不在官方移动端写死某个作者的服务器、模型或 Key；
- 不保留尚未发布版本的历史 schema 和一次性过渡代码；
- 不把 OpenAI、Anthropic、Gemini 的协议差异泄漏进核心业务层。
